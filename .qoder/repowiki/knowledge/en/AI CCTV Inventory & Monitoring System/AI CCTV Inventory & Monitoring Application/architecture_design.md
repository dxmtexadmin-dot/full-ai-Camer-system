Layered FastAPI app organized into four packages plus shared infrastructure:
- `api/` — route modules (`auth`, `cameras`, `employees`, `equipment`, `events`, `pages`, `reports`, `settings`) each exposing a single `router`; shared FastAPI dependencies (session auth, CSRF, role checks, Jinja2 template rendering) live in `api/deps.py`.
- `models/` — SQLAlchemy declarative models (`camera`, `employee`, `equipment`, `ledger`, `user`) plus an `enums.py` of domain enums; importing `app.models` registers mappers on the shared `Base.metadata`.
- `services/` — pure business logic per domain (`camera_service`, `employee_service`, `equipment_service`, `event_service`, `evidence_service`, `tracking_service`, `pipeline_service`, `yolo_service`, `face_service`, `google_sheets_service`, `monitoring_service`, `association_service`, `audit_service`, `inventory_service`, `settings_service`, `bootstrap`); `overlay.py` and `types.py` are cross-cutting helpers.
- `ui/` — Jinja2 templates under `templates/` and static assets under `static/`, mounted at `/static`.
- Shared layer: `main.py` creates the `FastAPI` instance, wires lifespan (logging init, DB bootstrap, monitoring start/stop), mounts routers, and installs global exception handlers; `config.py` provides a frozen `Settings` dataclass loaded from env vars via `python-dotenv`; `database.py` owns the process-wide SQLAlchemy engine/session factory and exposes `get_db()` as a FastAPI dependency plus `session_scope()` for background workers.
Dependency direction is strictly one-way: `api` → `services` → `models` + `database`; `main` orchestrates everything. External ML/runtime concerns (YOLO, InsightFace, RTSP cameras, Google Sheets) are isolated behind service classes so API routes stay thin.
